# تشغيل وكيل SHADOW بالذكاء الاصطناعي — دليل عربي

## ما الذي يعمل الآن؟
1. **الوضع المحلي:** يعمل داخل صفحة التخطيط، ويجيب من قواعد محددة وبيانات الخطة والأرصدة المحملة. يحتفظ بالمحادثة والملاحظات التي تطلب حفظها في هذا المتصفح فقط.
2. **الوضع الذكي عبر الخادم:** ملفات الواجهة والـ Worker جاهزة لربط المحادثة بنموذج لغوي عبر OpenAI Responses API. يحتاج هذا الوضع إلى نشر الـ Worker وإضافة مفتاح API كسرّ على الخادم. لا تضع المفتاح في صفحة HTML أو في محادثة ChatGPT.

## نشر الخادم عبر Cloudflare Workers
> قد يترتب على استخدام API تكلفة حسب النموذج وحجم الطلب. راجع حسابك وتسعير API قبل التشغيل. مفتاح API ليس هو اشتراك ChatGPT.

1. أنشئ حساب Cloudflare وافتح **Workers & Pages** ثم أنشئ Worker جديدًا.
2. انسخ محتوى `worker.js` إلى محرر الـ Worker، ثم احفظ وانشر.
3. في إعدادات الـ Worker، افتح **Settings → Variables and Secrets**:
   - أضف **Secret** باسم `OPENAI_API_KEY` وضع مفتاح API الخاص بك.
   - أضف **Secret** باسم `SHADOW_ACCESS_TOKEN` بقيمة عشوائية طويلة، واحتفظ بها لنفسك. أدخل القيمة نفسها في واجهة SHADOW. لا تستخدم مفتاح OpenAI كرمز وصول.
   - أضف متغيرًا نصيًا باسم `ALLOWED_ORIGIN` وقيمته الأصل الدقيق لصفحة GitHub Pages، مثل `https://mtarkg2025-lang.github.io` (لا تضف مسار المجلد).
   - اختياريًا أضف `SHADOW_MODEL` باسم نموذج متاح لحساب API. الافتراضي الحالي `gpt-5-mini`؛ إذا لم يكن متاحًا لحسابك غيّره إلى نموذج متاح.
4. أعد نشر الـ Worker بعد ضبط المتغيرات. لا تفعّل CORS لكل المواقع؛ اسمح فقط بأصل GitHub Pages المحدد.
5. انسخ عنوان Worker المنشور الذي ينتهي عادةً بـ `.workers.dev`.
6. افتح صفحة SHADOW، ثم قسم **محادثة شادو**. ألصق عنوان Worker ورمز `SHADOW_ACCESS_TOKEN` واضغط **حفظ إعداد الاتصال**. ستظهر رسالة موافقة قبل حفظ الاتصال.
7. أرسل سؤالًا تجريبيًا مثل: «لخص حالة الخطة واذكر البيانات التي تمنع اعتمادها». إذا فشل الاتصال، اقرأ رسالة الخطأ وتحقق من عنوان الخادم، السر، النموذج، وقيمة `ALLOWED_ORIGIN`.

## ماذا يرسل الوكيل إلى النموذج؟
عند تفعيل عنوان الخادم، ترسل الواجهة آخر رسائل المحادثة، وسياقًا مختصرًا من دليل الأصناف والخطة والاحتياج والأرصدة وإجراءات العقل والملاحظات المحفوظة والمصادر المرفوعة. قد يتضمن ذلك بيانات تشغيل داخلية؛ لا تفعّل الربط إلا على جهاز وحساب وخادم تثق بها، وارفع الحد الأدنى اللازم من البيانات. يرسل الـ Worker الطلب إلى `https://api.openai.com/v1/responses` مع `store: false`. هذا الإعداد لا يعني وحده ضمان عدم احتفاظ مزود الخدمة بأي بيانات وفق جميع السياسات؛ راجع شروط حساب API وسياسات البيانات الحالية.

## حدود وضوابط
- هذا وكيل استشاري: يحلل ويقترح ولا ينفذ صرفًا أو استلامًا أو شراءً أو تعديلًا للأرصدة.
- لا توجد حتى الآن أدوات تنفيذ مرتبطة بأودو أو قاعدة مخزون مركزية.
- الملاحظات والمحادثة المحلية لا تتزامن بين الأجهزة. صدّر السجل دوريًا إذا أردت الاحتفاظ به.
- البيانات التي ترفعها للمحادثة تُقرأ من الورقة الأولى/المحتوى النصي، بحد أقصى 1 ميجابايت للملف، و500 صف و40 عمودًا و250 حرفًا للخلية؛ إجمالي المصادر المحفوظة محدود لتفادي امتلاء تخزين المتصفح.
- رمز الوصول يمنع الطلبات غير المصرح بها عند معرفة عنوان Worker، لكنه ليس نظام هوية كاملًا. حدّثه إذا شاركته بالخطأ، وفعّل قاعدة Rate Limiting من Cloudflare للحدّ على مستوى الشبكة؛ الحدّ الداخلي بالكود أفضلية إضافية وليس بديلًا عن ذلك.
- المتصفح يحفظ رمز الوصول محليًا. لا تستخدمه على جهاز مشترك أو غير موثوق، ولا تعتبر عنوان Worker وحده سرًا.
- معادلة الاحتياج في التطبيق تقديرية حتى يعتمدها الإنتاج. لا تُعامل كمكوّنات/BOM معتمدة.
- يجب التحقق من جميع توصيات النموذج على المصدر الأصلي واعتماد مسؤول المخزون/الإنتاج/سلسلة الإمداد قبل التنفيذ.
